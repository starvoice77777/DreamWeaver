# 离线队列与冲突策略（契约，延后实现）

> 状态：阶段 3 尾巴，**仅文档**；阶段 4 上传不依赖本能力。  
> 日期：2026-08-01  
> 联调基线：`integration/frontend-backend`

## 1. 目标

在短暂断网或 API 不可达时，用户对「已登录远程态」的写操作可本地排队，恢复后按序回放，避免静默丢收藏 / 设置 / 显式保存。

本地演示模式（`ServiceBackendMode.local`）不走此队列。

## 2. 可入队的事件

| 类型 | 对应 API | 说明 |
|------|----------|------|
| `favorite_patch` | `PATCH /v1/users/me/scene-states/{id}` | 收藏开关 |
| `settings_put` | `PUT /v1/users/me/settings` | 全量或合并后的设置快照 |
| `private_scene_save` | draft PUT + `POST .../save` | **仅**用户确认保存后入队 |

不入队：拖拽混音、音量、试听、游客读接口。

## 3. 队列行为

- 存储：设备本地（UserDefaults / 文件均可）；按 `enqueued_at` **FIFO**。
- 出队：网络恢复且 `isRemoteAuthenticated` 时，串行发送；单条失败则停止并保留队头（避免乱序）。
- **401 / 会话失效**：清空队列中需鉴权项，提示重新登录；不自动用过期 refresh 死循环。
- 去重：同 `scene_id` 的连续 `favorite_patch` 可折叠为最后一次；`settings_put` 同理只保留最新快照。

## 4. 冲突策略

| 资源 | 策略 |
|------|------|
| 收藏 / 最近打开 | 以后端最终状态为准；出队成功后用 `GET /v1/home` 或 PATCH 响应回填 UI |
| 设置 | 服务端字段覆盖本地；出队的是「离线期间最后一次本地快照」 |
| 个人场景显式保存 | 本地草稿优先：出队时以当前本地 sources 再 PUT draft + save；若服务端 `saved_version` 更高，保存成功后以服务端 detail 刷新，并提示「已生成新版本」 |

不做自动三路合并；不做「隐式覆盖官方场景」。

## 5. 与阶段 4 的关系

上传会话（预签名 PUT）**默认要求在线**；失败由用户重试，不入本队列（大文件与签名过期不适合静默重放）。

## 6. 实现时机

建议在阶段 4 上传联调稳定后，或阶段 7 陪伴上报一并落地。落地前客户端继续：在线走 Remote API，离线写本地 Demo 持久化即可。
