# 联调测试清单与缺陷记录（当前：Xcode 模拟器优先）

> 分支：`integration/frontend-backend`  
> **本阶段目标**：Mac Xcode **模拟器**逐功能测与修；真机回归后置  
> 更新：2026-08-05

**用法**：按下方推荐顺序，一次只测一个功能块；该块全部勾选通过后再进下一块。未达预期时用「六、缺陷记录」登记，修完后只回归该编号 + 其依赖项。

### 模拟器 vs 真机（本阶段约定）

| 项 | 模拟器（本阶段） | 真机（后置） |
| -- | ---------------- | ------------ |
| 跑法 | Xcode → 任选 iPhone 模拟器 → Run | 实机安装 |
| 默认 API 基址 | 代码默认 `http://127.0.0.1:8000`（API 须在 **同一台 Mac** 上） | 局域网 IP，如 `http://192.168.x.x:8000` |
| Windows 跑 API 时 | 模拟器里的 `127.0.0.1` **连不到** Windows；设置里改成 Windows 的局域网 IP，且 API 监听 `0.0.0.0` | 同左，用局域网 IP |
| Apple 登录 (J) | **本阶段跳过**（用开发登录 B） | 再测 |
| 听感 / 空间感 | 耳机或 Mac 扬声器可测有无声、左右大致变化；精细 HRTF 以真机为准 | 正式听感验收 |
| 断网 (K1) | 可用模拟器 Features → Network Link Conditioner，或停 API 进程 | 关 Wi‑Fi / 飞行模式 |

## 七、修复循环（建议）

1. 按「〇」顺序测完当前功能块全部用例  
2. 失败立即开 `BUG-n`，**不要跳过未测完的同块用例**（除非崩溃阻塞）  
3. 一块内 P0 失败修完 → 只回归该块 + 表中「依赖」块的冒烟项  
4. 最小通过标准 7 条全绿 → 再扫 H / K；I / J 可另排  

把缺陷贴到对话或 issue 时，保留 `关联用例` 编号，便于对照本文回测。
