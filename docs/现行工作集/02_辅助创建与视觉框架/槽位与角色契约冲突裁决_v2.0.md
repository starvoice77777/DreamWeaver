## 1. 版本与采用规则

本修订依据用户“先解决冲突再进行后续操作”的要求，保留现行产品的框架数量上限和最小结构，修正 `808cba5` 中偏离产品的定义，并将原先模糊的区域、角色与身份约定具体化。没有启动前端下一切片或新生成接口实现。

- 注册表与五份脚本版本升级到 `2.0.0`。
- 单脚本结构契约升级为 `dreamweaver-structure-script-v2`：新增必需的 `occupancy_constraints`，统一播放类别。旧解析器必须拒绝未知版本，不能忽略新约束。
- 注册表外层字段结构未变，仍使用 `dreamweaver-structure-script-registry-v1`；其内容版本以 `registry_version=2.0.0` 标识。
- 目录 `结构脚本注册表_v1` 与文件名中的 `.v1.json` 暂时保留为既有路径；不得从路径推断内容版本。旧 `1.0.0` 可从 Git 提交 `808cba5` 追溯；缓存与日志必须使用实际版本。
- 所有脚本仍是 `implementation_ready / pending_listening_review`，正式运行仍需审核通过。
- 下表为本次规则裁决，JSON 脚本是它的机器可读表达。旧审计回执保留为问题发现记录，不再作为当前接线表。

随分支交付的依据文档：[声音组合与脚本规范](./五种声音组合方式与结构脚本系统_v1.3.md)、[素材绑定与角色规范](./声音组合素材绑定与内容预设规范_v1.2.md)、[辅助创建交互规范](./辅助创建交互逻辑_v1.3.md)。三份文档均包含本次修订说明。

## 2. 容量与最小结构

| 框架 | 最终总数 | 最小结构 | 本次消除的冲突 |
| --- | --- | --- | --- |
| 内外交织 | 2–4 | 外部 1 + 内部稳定 1 | 外部固定 1；内部细节恢复为 0–2，四对象组合可达 |
| 安稳包围 | 2–3 | 底层 1 + 包围环境或细节至少一项 | 不再强制包围环境；细节最多 1；总上限恢复 3 |
| 远近分层 | 2–3 | 远/中/近中至少两组，各组最多 1 | 不再同时强制远和中；中景允许有审核依据的 bed，支持中+近 |
| 主声突出 | 2–4 | 底层 1 + 焦点对象 1–3 | A/B/C 只是视觉位置，共用一个对象槽 |
| 两侧舒展 | 2–4 | 背景 1 + 左/右/前至少一组 | 不再强制左右同时存在；两侧都在仍是推荐结构 |

全局预算保持：`bed=1`、`ambience=0..1`、`F=action+trigger+voice=0..3`、`1<=ambience+F<=3`、`voice<=1`。再叠加各框架总上限。所有计数均按逻辑对象，包含用户选择和系统补充。

草稿可以暂时不满足最小结构；请求 Schema 继续允许 1–4 个用户对象。安稳包围/远近分层收到四对象请求时，后续框架校验应明确拒绝或要求用户调整，不能静默丢弃，也不能因基础请求门禁通过而称可播放。

系统补充只提供产品已允许的承接层：内外交织可补外部或内部稳定层，安稳包围补底层，远近分层补远景，主声突出补底层，两侧舒展补背景。缺少其他组时返回澄清，不自行制造用户未选的细节或左右近场。补充须可见、可试听、可拒绝；被拒绝的对象不得静默补回。

旧 `object_a/b/c` 绑定以及任何旧脚本区域值必须经版本化迁移、重新检查适配证据后才供新规则使用；不得在请求门禁里悄悄归一化以绕过精确匹配。审核记录迁移不自动获得 `approved`。

## 4. 角色与播放类别

角色分配责任固定：素材/内容审核人员维护 `FrameBindingProfile` 的默认角色、允许角色及适配证据；后端场景解析器联合内容预设和脚本确定最终角色；前端展示审核候选及校验结果。素材目录只保存推荐角色，不保存唯一场景角色。

最终角色必须同时属于审核绑定和结构槽的允许集合，并满足整组预算。区域默认角色是推荐值，不能在缺少具体绑定时自动赋给所有资源。底层槽只允许 bed；内外交织的外部/内部稳定可以在合法审核范围内互为 bed/ambience。远近分层允许中景承担 bed，是为实现产品已定义的“中+近”最小结构；没有允许 bed 的中景绑定时，该具体组合仍不可用，不能改写资源角色凑数。

`playback_class` 在绑定与结构脚本中统一为：

| 类别 | 含义 |
| --- | --- |
| sustained | 持续承接或环境声音；是否循环由 loop_requirement 和审核编译策略决定 |
| episodic | 离散事件或间歇动作 |
| continuous_trigger | 持续质感的触发声音；不表示可以无限循环 |
| voice | 人声内容 |

`continuous / bounded_loop / oneshot / phrase_sequence` 不再作为结构槽的播放类别。它们涉及执行方式，不能从旧标签机械地推出新审批绑定；真实绑定迁移须由素材审核确定。`loop_requirement`、变体策略和具体播放事件仍单独处理。播放类别不等于场景角色。

当前联调代码 `9703d19` 的 `FrameBinding` 仍缺角色与播放类别，内容预设投影仍缺角色解析策略。这里解决字段含义和责任，不代表这些服务已实现。测试 fixture 或仅有表头的 CSV 不能用作生产候选。

## 5. 身份、变体和重复

本次固定以下目标规则，供后续实现使用：

- `sound_object_id` 是草稿中的实例身份。用户对象由前端首次成功加入时生成 UUID 字符串；移动、恢复、网络重试、同一逻辑对象切换审核变体都保留。失败的加入不写入草稿或占位。
- 目录应提供稳定的 `catalog_sound_id`，表示可识别的一种逻辑声音及其已审核变体集合。它与草稿实例 ID、`resource_key`、轨道 ID 分开。该字段是后续目录交付要求，不是当前请求新增字段。
- 同一草稿不允许重复 `catalog_sound_id`，也不允许不同实例通过同一 `resource_key` 绕过去重。不同资源若属于同一逻辑声音的变体，仍只占一个对象名额。缺少分组数据时标为未适配，不能用文件名推断。
- 变体切换保留实例 ID；替换成另一种逻辑声音或删除后重新添加时生成新实例 ID。若原对象是焦点，替换操作须同步更新焦点引用；不得残留指向已删除对象的 `focus_target`。
- 系统补充由后端生成并返回稳定实例 ID；同一幂等请求重放复用原结果。前端接受后保存原 ID，不再次生成。用户拒绝补充后以现有资源排除字段及草稿逻辑对象排除记录保持意图；后端需扩展契约后才能跨变体表达对象级排除，不能私加字段。

## 6. 请求分槽与数据交付边界

沿用 `ai-scene-generation-v1` 请求：前端只提交已有字段，`desired_zone` 使用审核绑定的规范区域；`slot_id`、UI 位置、最终角色、`catalog_sound_id` 均不临时加入请求。

后端根据 `resource_key + framework_id` 解析唯一审核绑定，再结合区域、播放类别、角色和脚本分槽。内外交织 `inside` 下两个结构槽的角色集合不重叠，可按可行角色分配区分。若一个绑定同时适配两槽且预设不能唯一确定，必须澄清，不用槽顺序默默覆盖用户选择。UI 不把本地分类预览宣称为服务端最终分槽；需要承诺用户指定槽位时，先升级请求契约。

后续候选数据应由服务端提供版本化投影，包含 `catalog_sound_id`、资源/审核变体、绑定 ID/版本、规范区域、默认/允许角色、播放类别、可用槽位及预设兼容性；依赖版本包含目录、绑定索引、脚本与预设，涉及运动时增加运动注册表版本。可用槽位由后端按这些依赖计算，不由前端按名称猜测。

缺少任一必要审核数据，候选不得进入可生成状态。当前没有可调用的新候选/生成路由；路由、公开错误响应和幂等执行仍属于后续接口切片，不能伪称已上线。
