# DreamWeaver 声音组合素材绑定与内容预设规范

版本：`v1.2`

状态：现行数据与内容映射规范

日期：2026-09-19

2026-09-20 契约修订：容量与最小结构保持产品口径；区域、角色、播放类别和身份规则按[冲突裁决 v2.0](./槽位与角色契约冲突裁决_v2.0.md)统一，并对应脚本 `2.0.0`。本文下表已同步；真实绑定与候选 API 尚待交付。

## 1. 目的

本文补齐声音组合方式、内部框架、内容预设、素材和最终时间线之间的映射，解决以下问题：

- 素材入库时应提前确定什么；
- 哪些信息只能在具体场景中确定；
- 五种声音组合方式如何通过内部框架限制画布区域和素材推荐；
- 十个内容预设如何进入五个结构脚本族；
- 用户只选一个声音时，系统如何补齐最小可播放结构。

## 2. 数据层级

```text
AssetCatalog
  素材是什么、质量如何、推荐角色是什么
    ↓
FrameBindingProfile
  素材在某种声音组合方式的内部框架中可放在哪、默认如何使用、允许怎样替换
    ↓
ContentPreset
  用户为什么听、当前状态、场景主次与触发模式
    ↓
SceneDraft
  本次选择的素材、最终角色、声音组合状态和脚本实例
    ↓
timeline.json / tracks.csv
  可执行时间、音量、空间和播放事件
```

## 3. 角色归属

### 3.1 素材库

素材库保存：

- `material_category`
- `recommended_roles`
- `recommended_goals`
- 听感评分和风险标记
- 授权与QC状态

素材库不保存唯一 `scene_role`。

### 3.2 声音组合绑定（内部仍使用框架字段）

`FrameBindingProfile` 保存：

| 字段 | 说明 |
| --- | --- |
| `resource_key` | 素材短键 |
| `framework_id` | 五种声音组合方式对应的内部框架 ID 之一 |
| `visual_zone` | 在画布上的语义区域 |
| `default_role` | 当前组合方式中的默认角色 |
| `allowed_roles` | 当前组合方式允许分配的角色集合 |
| `replacement_group` | 可以直接替换的素材组 |
| `playback_class` | `sustained` / `episodic` / `continuous_trigger` / `voice` |
| `loop_requirement` | `required` / `forbidden` / `optional` |
| `variant_strategy` | 变体轮换方式 |
| `motion_preset_family` | 允许使用的运动预设族 |
| `allowed_content_presets` | 可以进入的内容预设 |
| `recommended_goals` | 推荐使用目标 |
| `risk_flags` | 风险标记 |
| `binding_status` | `draft` / `listening` / `approved` / `rejected` |

同一素材可以在不同组合方式中有不同绑定；在同一内部框架的第二层只暴露一个默认绑定。

### 3.3 场景草稿

最终 `scene_role` 由以下信息共同决定：

1. 内容预设要求；
2. 绑定记录的 `default_role` 和 `allowed_roles`；
3. 当前场景已有声音及主次关系；
4. 用户是否锁定或手动调整该声音。

最终角色必须属于 `allowed_roles`，并写入 `SceneDraft` 和 `tracks.csv`。角色改变属于场景变化，不修改素材库母记录。

## 4. 组合方式、内部区域与角色范围

| 用户名称 | 内部 `framework_id` |
| --- | --- |
| 内外交织 | `boundary_gate` |
| 安稳包围 | `enclosure_control` |
| 远近分层 | `depth_reveal` |
| 主声突出 | `focus_selector` |
| 两侧舒展 | `nearfield_width` |

| `framework_id` | `visual_zone` | 默认角色 | 允许角色 |
| --- | --- | --- | --- |
| `boundary_gate` | `outside` | `ambience` | `bed, ambience, action` |
| `boundary_gate` | `inside` | `bed` | `bed, ambience, action, trigger, voice` |
| `enclosure_control` | `base` | `bed` | `bed` |
| `enclosure_control` | `surround` | `ambience` | `ambience, action` |
| `enclosure_control` | `detail` | `action` | `action, trigger, voice` |
| `depth_reveal` | `far` | `bed` | `bed, ambience` |
| `depth_reveal` | `mid` | `ambience` | `bed, ambience, action` |
| `depth_reveal` | `near` | `action` | `action, trigger, voice` |
| `focus_selector` | `base` | `bed` | `bed` |
| `focus_selector` | `focus_field` | `action` | `ambience, action, trigger, voice` |
| `nearfield_width` | `background` | `bed` | `bed` |
| `nearfield_width` | `left_near/right_near` | `trigger` | `action, trigger` |
| `nearfield_width` | `front_companion` | `voice` | `ambience, action, trigger, voice` |

这些区域只表达粗粒度空间语义。具体 `angle`、`radius` 和关键帧仍由脚本编译器产生，并通过空间安全校验。

`object_a/b/c` 为前端视觉位置，共用 `focus_field`，不再作为审核绑定的区域值。表中角色是区域允许范围；具体资源仍须有审核绑定，具体结构槽还可收窄范围。中景只有在其审核绑定允许 bed 时才可承担底层，不能凭区域默认赋权。`playback_class` 与脚本统一使用上述四类；执行层的循环或事件模式不与其混用。

## 5. 首版内容预设映射

以下映射用于控制首版数量，不代表已经完成听感验证。初始状态统一为 `draft`，经试听后才能升为 `listening` 或 `approved`。

| 内容预设 | 默认组合方式（内部 ID） | 结构重点 | 主要目标 |
| --- | --- | --- | --- |
| `rain_sleep_onset` | `boundary_gate` | 内部稳定、外部连续雨幕 | `sleep_onset` |
| `rain_parasol` | `boundary_gate` | 外部雨幕、内部檐下与稀疏细节 | `sleep_onset, stress_recovery` |
| `pink_noise_night_tide` | `enclosure_control` | 稳定遮蔽、低动态包围层 | `sleep_onset, sleep_maintenance` |
| `hearth_quiet_night` | `enclosure_control` | 室内底层、包围炉火、低密度木柴细节 | `stress_recovery` |
| `stream_recovery` | `depth_reveal` | 远景氛围、中景溪流、可选近景细节 | `stress_recovery` |
| `night_tide` | `depth_reveal` | 远景海风、中景潮汐、近景岸线纹理 | `sleep_onset, stress_recovery` |
| `page_turning_sleep` | `focus_selector` | 房间底层、翻页、书写等多物体主次 | `asmr_relaxation, sleep_onset` |
| `wood_tapping_slow` | `focus_selector` | 稳定底层、多种木质对象焦点 | `asmr_relaxation` |
| `care_brush_towel` | `nearfield_width` | 左右近场刷拭与可选正前陪伴 | `asmr_relaxation, process_companionship` |
| `breathing_guidance` | `nearfield_width` | 稳定背景、正前人声、克制近场提示 | `stress_recovery, sleep_onset` |

用户不需要先在十个预设中做一次完整选择。系统根据入口目标、声音组合方式和首个核心声音筛出最合适预设；若仍有明显不同结果，再用少量卡片确认。

## 6. 各声音组合方式的最小结构

| 内部 `framework_id` | 最小可生成结构 | 推荐结构 | 建议总数 | 硬上限 | 系统可补充 |
| --- | --- | --- | --- | --- | --- |
| `boundary_gate` | 外部 1 + 内部稳定 1（承接用户核心声音） | 底层 1 + 外部环境 1 + 内部细节 0–2 | 3 | 4 | 室内底层或外部连续层 |
| `enclosure_control` | `base` + `surround/detail` 至少一项 | 底层 1 + 包围环境 1 + 细节 0–1 | 2–3 | 3 | 稳定底层 |
| `depth_reveal` | 至少两个不同景深组，各组最多 1；bed 位于远或中 | 远景底层 1 + 中景主体 1 + 近景细节 0–1 | 2–3 | 3 | 低注意力远景底层 |
| `focus_selector` | `base` + 至少一个对象组 | 底层 1 + 可切换物体／触发音 2–3 | 3–4 | 4 | 房间稳定底层 |
| `nearfield_width` | `background` + 至少一个近场或前方组 | 背景 1 + 左右近场 2 + 可选正前人声 0–1 | 3–4 | 4 | 低强度稳定背景 |

无论系统补什么，都必须在确认前可见、可试听、可拒绝。

所有组合方式同时服从统一分类预算：`bed=1`、`ambience=0..1`、`action + trigger + voice=0..3`、`voice<=1`，普通声音物体总数为 2–4 个。独立环境层和前景声音合计不得超过三个；用户选择与系统补充使用同一预算。数量按逻辑声音物体计算，素材变体不重复占名额。

## 7. 替换等级

### A级

同一 `replacement_group`，播放类型、循环要求、允许角色和运动预设兼容。可以直接替换资源并只重编当前轨。

### B级

内容兼容，但需要调整单轨时长、循环、淡入淡出或运动预设。完成单轨校验后进入场景。

### C级

会改变角色、触发模式、内容预设或结构脚本。进入后台适配或建议其他声音组合方式，不进入即时路径。

## 8. 状态门禁

```text
draft → listening → approved
                   ↘ rejected
```

- `draft`：字段齐全但未试听；
- `listening`：正在进行耳机、外放和长时试听；
- `approved`：通过授权、素材QC、组合方式适配和听感测试；
- `rejected`：不适合当前声音组合方式或风险不可接受。

任何AI生成或用户上传的新素材都从 `draft` 开始，不能直接进入即时推荐。

## 9. 场景生成时的确定顺序

```text
确定 primary_goal 和状态
→ 确定声音组合方式及对应 framework_id
→ 匹配 content_preset_id
→ 读取 approved FrameBindingProfile
→ 用户选择并锁定核心声音
→ 补足最小结构
→ 为每条引用确定最终 scene_role
→ 实例化脚本并编译 timeline
→ 校验与试听
```

## 10. 验收

- 素材母记录不存在唯一 `scene_role`；
- 每条即时候选存在唯一批准绑定；
- 最终角色属于绑定允许角色；
- 十个内容预设均映射到五种声音组合方式之一；
- 每种声音组合方式都定义了最小结构和补充规则；
- 每个候选组合同时通过分类预算、组合方式硬上限和总数上限；
- 系统补充可见、可试听、可拒绝；
- 未试听绑定不能标为 `approved`。
