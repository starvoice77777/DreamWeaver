# DreamWeaver 场景素材包制作与交付规范 v1.0

## 1. 目的与真相源

本规范把一个场景从构想到可进入 App 的交付物整理为独立素材包。每个场景只能有一个 `scene_id`，所有可执行信息以 `scene/timeline.json`、`scene/tracks.csv` 和实际音频文件为准；Word、PDF 与图片只用于阅读和审阅，不得成为唯一真相源。

## 2. 标准目录

```text
sc_xxx_v01/
├─ README.md
├─ docs/
│  ├─ 场景时间戳与素材清单.docx
│  └─ 场景说明.md
├─ scene/
│  ├─ scene_manifest.json
│  ├─ timeline.json
│  ├─ tracks.csv
│  └─ source_map.csv
├─ audio/
│  ├─ master/          # 时间线实际引用的推荐母带
│  ├─ alternatives/    # 仅供人工 A/B 试听，不可被正式时间线引用
│  └─ demo/            # 预渲染长版或演示混音，不等于正式母带
├─ content/
│  ├─ phrases.csv      # 无人声场景保留表头并为空
│  └─ voice_bindings.csv
├─ qc/
│  ├─ asset_qc.csv
│  ├─ scene_acceptance.md
│  └─ reports/
└─ licenses/
   └─ license_manifest.csv
```

不得把源视频、网络参考音频或未授权声样放进 `master/`。原始素材另行归档，素材包只放经过命名、处理和状态标记的文件。

## 3. 场景类型

### 3.1 无文本、无人声环境场景

- `phrases=[]`，不创建 voice 轨。
- 通常由 1 条持续底层、1 条主环境和 0–2 条缓慢变化层组成。
- 不使用音乐、雷声、突然鸟叫或高频触发音；变化间隔通常不少于 90 秒。
- 每条轨必须说明进入、退出、空间位置、播放时长、循环方式和默认音量。

### 3.2 有文本、有人声过程场景

- 每句短提示必须有唯一 `phrase_id`，记录精确文本、真实音频时长、审核状态和 `voice_binding`。
- 短提示应描述当下动作或放松指令，信息量低、句式自然、单句一般 6–18 字；避免连续讲故事、健康承诺、命令式压迫和需要用户思考的内容。
- 人声开始时环境轨按场景设定 duck，句尾真实时长加约 300ms 后恢复。
- 动作声使用 `oneshot`；持续背景使用 `loop`。不得为了对齐文字把音频明显变速。
- 用户或亲友声线只在授权、用途限制和撤回删除机制完成后使用；未授权声线不得进入素材包。

## 4. 音频与命名要求

### 4.1 文件名

```text
dw_{source}_{layer}_{semantic}_{playmode}_{scene}_{distance}_v{version}_t{take}.wav
```

- `source`：`official`、`user`、`generated`。
- `layer`：`env`、`amb`、`trg`、`vox`。
- `playmode`：`loop`、`oneshot`。
- `scene`：统一使用项目维护的 `sc_*` 缩写，不得个人自造。
- `vXX`：可听内容或母带处理变化时递增；`tXX`：同版本下的试听备选。

工程引用使用稳定的 `resource_key`，不得把长文件名当资源键。推荐母带通常为 `t01`；`t02` 等放入 `alternatives/`。

### 4.2 格式与响度

| 图层 | 综合响度建议 | 真峰值 | 其他要求 |
| --- | --- | --- | --- |
| `environment + loop` | `-25 ±2 LUFS` | `≤ -3 dBTP` | 持续稳定，无惊吓瞬态 |
| `ambience + loop` | `-23 ±2 LUFS` | `≤ -3 dBTP` | 可辨识但不遮盖底层 |
| `trigger + oneshot` | `-22 ±2 LUFS` | `≤ -3 dBTP` | 首尾干净，不机械连发 |
| `voice + oneshot` | `-18 ±1 LUFS` | `≤ -3 dBTP` | 字音清楚，比环境高约 5–7 LU |

- 正式母带：48 kHz、PCM WAV；环境轨优先立体声，人声可单声道。
- 不只看峰值归一，必须记录 Integrated LUFS 与 True Peak。
- 保留自然版本，不做无依据的重降噪、重压缩、立体声扩展或高频塑形。
- 循环母带建议 30–180 秒；较短素材允许用于演示，但必须标记 `qc_pending` 和交叉淡化要求。

## 5. 时间线字段要求

每条轨至少填写：`track_id`、`resource_key`、`layer`、`master_file`、`start_seconds`、`asset_duration_seconds`、`playback_duration_seconds`、`loop`、`requires_engine_crossfade`、`crossfade_ms`、`default_volume`、`angle`、`radius`。

- `angle` 使用弧度，范围 `-π…π`；`radius` 使用项目统一的归一化距离。
- `asset_duration_seconds` 是文件真实时长；`playback_duration_seconds` 是场景需求时长。
- `loop=true` 时必须明确填写 `requires_engine_crossfade`。
- `requires_engine_crossfade=true` 时必须填写 `crossfade_ms`，通常 600–1500ms，且小于母带时长一半。
- 进入/退出淡化与循环接缝交叉淡化是两件事，分别填写。
- 同一资源在两个独立时段从头播放时，创建两个 `track_id` 实例。

完整后端执行规则见 `scene-creation-spec-v1.1.md` 第 11 节。

## 6. 制作流程

1. **定义场景**：确认目标听感、是否有人声、总时长、外放/耳机策略和禁止元素。
2. **建立轨道需求**：先写 `tracks.csv`，状态为 `planned`；确定每条轨的语义和层级，不先堆素材。
3. **收集与授权**：保存来源、授权范围、署名和到期条件；网络成品只能作为 `ref`。
4. **分析母带**：检测格式、采样率、声道、时长、LUFS、dBTP、削波、噪声、音乐、首尾断点和频谱风险。
5. **按检测结果处理**：重采样、适度增益、限峰、必要的频段修正和循环处理；不覆盖原始文件。
6. **建立时间线**：先完成 `timeline.json`，再同步 Word 时间戳文档；所有文件引用必须能在素材包内解析。
7. **schema 与引用校验**：检查 JSON、UUID、时间范围、角度单位、文件存在性和状态门禁。
8. **实机场景试听**：手机外放、耳机、至少 2 分钟连续循环、拖动距离、暂停恢复和离线资源测试。
9. **状态升级**：`raw → ref/qc_pending → master`。只有授权与 QC 均通过的文件才可进入正式 catalog。
10. **冻结交付**：生成版本号、校验值和变更记录；压缩包内不得包含未引用临时文件。

## 7. 验收门禁

- 时间线中引用的每个 `track_id`、`resource_key` 和 `master_file` 均存在。
- 所有音频为 48 kHz，响度与真峰值满足图层要求。
- `loop=true` 的轨连续试听至少 2 分钟，无明显接缝、鼓包、掉音或短周期重复；不能自然循环时已配置工程交叉淡化。
- 多轨同时播放无削波，主次关系符合场景设计；距离拖动的层次由空间衰减产生，不靠修改母带响度。
- 场景开始和结束无硬切；异常素材丢失时能降级而不播放突发替代音。
- 有人声场景已校验文案、真实音频时长、duck、授权和撤回删除机制。
- `scene_manifest.release_ready` 只有在全部资产为 `master` 且许可证为 `approved` 时才可设为 `true`。

## 8. 职责边界

- 产品：场景目的、时间戳、文案、主次关系和最终听感验收。
- 素材：母带收集、命名、来源、处理、指标记录和试听备注。
- 后端/数据：schema、资源键、时间线校验、catalog 与降级逻辑。
- iOS/前端：播放、空间位置、循环交叉淡化、缓存、外放/耳机实机验证。

任何一方修改可听内容、母带文件或时序后，都必须同步版本和变更记录，不能只改 Word。
