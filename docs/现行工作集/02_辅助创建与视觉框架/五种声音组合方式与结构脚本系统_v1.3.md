# DreamWeaver 五种声音组合方式与结构脚本系统

版本：`v1.3`

状态：用户命名、交互基线与底层兼容关系已确认

日期：2026-09-19

## 1. 目标

第二层不让AI从零编写时间线，而是让用户选择一种可理解、可操作的声音组合方式，再从已适配素材中选择声音。声音组合方式负责表达宏观关系，画布用相应图形呈现这种关系，素材绑定负责默认区域与允许角色，结构脚本编译成标准 `timeline.json`。

- 把长时间开放生成转为可预测的模板实例化；
- 让五种声音组合方式具有清晰、可预期的声学作用；
- 不要求用户理解“视觉框架”这一内部实现概念；
- 保留用户选择、删除、替换和微调权；
- 遵守声音角色、触发节奏、重复预算和空间安全规范；
- 第二层结果可以无损进入第三层。

## 2. 核心对象

### 2.1 `VisualFrameworkController`

产品层统一称为“声音组合方式”。工程层为兼容现有实现，继续使用 `VisualFrameworkController`、`framework_controller` 和 `framework_id`。每个第二层场景恰好有一个控制器；它通常不引用音频文件，而是标识结构脚本族、划分语义区域、提供一个宏观声学交互、约束素材和内容预设，并保存当前状态与受控声音组。

“视觉框架”只描述声音组合方式在画布上的图形表现，不再作为用户选择的产品类别。视觉造型可以迭代，但声音组合方式、声学边界和内部 ID 必须保持稳定。

### 2.2 `SoundObject`

声音物体引用一个或多个素材变体，例如雨、翻页、杯子、刷拭和人声。数量按用户可识别和操作的逻辑声音物体计算，不按底层文件或录音变体计算；一个声音物体轮换多个已审核变体仍只占一个名额。它可以有线稿和装饰动效，但装饰动效默认不控制音频。组合控制器（工程层 `framework_controller`）不计入数量。

### 2.3 `FrameBindingProfile`

绑定记录描述素材如何适配某种声音组合方式及其内部框架，不把最终 `scene_role` 固化为素材永久属性。

最小字段：

```text
resource_key
framework_id
visual_zone
default_role
allowed_roles
replacement_group
playback_class
loop_requirement
variant_strategy
motion_preset_family
allowed_content_presets
recommended_goals
risk_flags
binding_status
```

- 素材库保存 `recommended_roles`；
- 内部框架绑定保存 `default_role` 和 `allowed_roles`；
- 每次生成场景时根据内容预设和实际关系写入最终 `scene_role`；
- 只有 `binding_status=approved` 的记录进入即时路径。

## 3. 五种声音组合方式

用户只看到声音组合方式、结果描述和等价控件，不需要看到 `framework_id`、脚本名称或精确坐标。五种用户名称与内部实现一一对应：

| 声音组合方式 | 内部 `framework_id` | 图上操作与等价控件 | 声学作用（基线） | 提交反馈 |
| --- | --- | --- | --- | --- |
| 内外交织 | `boundary_gate` | 拉帘／开合；同参数滑杆 | `boundary_openness: 0..1`；外部相对突出程度变化，内部稳定或小幅补偿 | 松手后显示“已调整窗外声音 · 撤销” |
| 安稳包围 | `enclosure_control` | 包围结构吸附到三档；开阔／均衡／安稳按钮 | `open / balanced / enclosed`；稳定底层、未来细节密度与运动范围按审核方案改变 | 提示从后续事件生效 |
| 远近分层 | `depth_reveal` | 选近处／均衡／远处；对应层高亮 | `near / balanced / far`；相对混音与三套审核距离状态 | 展示当前突出层，不显示任意坐标 |
| 主声突出 | `focus_selector` | 拖焦点指示器到对象；或点主声目标按钮 | `focus_target: sound_object_id`；最多三个可选目标，影响持续声音主次及未来事件 | 显示当前主声名；不会立刻播放一次性事件 |
| 两侧舒展 | `nearfield_width` | 两侧结构收拢／展开并吸附三档；集中／自然／舒展按钮 | `focused / natural / wide`；使用审核过的近场运动预设 | 提示从下一事件或安全段落生效 |

### 3.1 内外交织 `boundary_gate`

视觉隐喻：窗、帘、舷窗或其他内外分隔结构。

```text
窗外底层／环境组
+ 窗内稳定组
+ 窗内可选细节组
```

控制参数：`boundary_openness: 0..1`

- 越打开，外部声音相对更突出；
- 越关闭，外部声音平滑减弱，内部声音保持稳定或小幅补偿；
- 关闭不使外部声音硬停；
- 不改变素材种类、事件时序和运动路径；
- 首版只使用音量和已验证位置，不假定低通、遮挡或动态混响能力。

语义区域：`outside`、`inside`。

### 3.2 安稳包围 `enclosure_control`

视觉隐喻：穹顶、床幔、围合罩或包裹结构。

```text
稳定底层
+ 包围环境层
+ 少量可选细节
```

控制参数：`enclosure_level: open | balanced | enclosed`

- `open`：层次稍丰富，允许较多但受限的环境运动和细节；
- `balanced`：使用预设默认状态；
- `enclosed`：稳定底层更突出，未来细节更稀疏，运动范围更小；
- 三个状态必须分别通过试听；
- 正在播放的短触发不被截断，密度变化只影响后续事件。

语义区域：`base`、`surround`、`detail`。

### 3.3 远近分层 `depth_reveal`

视觉隐喻：雾幕、景深层、帷幕或远近分层介质。

```text
远景持续组
+ 中景主体组
+ 近景低密度组
```

控制参数：`depth_reveal: near | balanced | far`

- 在远、中、近声音组之间执行平滑相对混音；
- 切换到三套预先验证的距离状态；
- 不改变声音角色和事件频率；
- 不生成任意轨迹；
- 所有移动继续通过完整路径和耳部禁行区校验。

语义区域：`far`、`mid`、`near`。

### 3.4 主声突出 `focus_selector`

视觉隐喻：聚光灯、桌灯、观察光束或焦点指示器。

```text
稳定房间底层
+ 物体组 A
+ 物体组 B
+ 可选物体组 C
```

控制参数：`focus_target: sound_object_id`

- 被照亮对象成为当前焦点；
- 持续声音平滑提高相对突出程度；
- 一次性事件不因切换焦点而立即触发；
- 焦点只影响后续事件选择和主次；
- 其他声音不删除，仍遵守不重叠和重复预算；
- 首版最多三个焦点目标。

语义区域：`base`、`focus_field`。`object_a`、`object_b`、`object_c` 仅为三个 UI 位置，共享 `focus_targets` 结构槽与 `focus_field` 区域；焦点仍引用稳定的 `sound_object_id`。

### 3.5 两侧舒展 `nearfield_width`

视觉隐喻：枕边双翼、近场环或两侧可展开结构。

```text
稳定背景
+ 左侧近场组
+ 右侧近场组
+ 可选正前方陪伴组
```

控制参数：`nearfield_width: focused | natural | wide`

- `focused`：位置更稳定，左右变化更小；
- `natural`：使用默认缓慢左右变化；
- `wide`：使用稍宽但已审核的运动预设；
- 当前事件不突然改道，从下一事件或安全段落生效；
- 不改变触发频率；
- 禁止快速绕头或穿越耳部禁行区。

语义区域：`background`、`left_near`、`right_near`、`front_companion`。

## 4. 交互状态、作用对象与时间线

### 4.1 临时试听

用户操作声音组合控件时，客户端可以对已加载轨道应用临时参数，提供即时反馈。临时状态不改变时间线版本，离开页面可以丢弃。界面必须以用户可理解的声音组或声音名称说明当前控制影响谁，不能只显示抽象图形或内部参数。

### 4.2 应用与保存

用户松手、选择离散状态或点击应用后：

1. 写入 `framework_controller.state`；
2. 根据控制器规则重编受影响的音量、事件计划或位置关键帧；
3. 当前短触发播放完成后，在最近安全边界生效；
4. 运行时间线、循环、触发和空间校验；
5. `timeline.version + 1`；
6. 保存后第三层可以看到对应轨道变化。

组合状态不能只存在客户端内存中，也不能在时间线之外永久改变播放结果。

### 4.3 手动编辑保护与覆盖确认

- 经过单声音轻量微调或第三层手动编辑的轨道写入 `manual_override_track_ids`，默认不受宏观控制覆盖；
- 宏观控制提交前先计算受影响轨道，区分“可直接应用”和“受保护”两组；
- 如果不会改动受保护轨道，可直接提交，并在反馈中说明实际作用对象；
- 如果会改动受保护轨道，必须展示影响清单，至少包含声音名称、轨道标识和将被改变的维度（音量、未来事件或运动状态）；
- 用户明确选择“仍应用到这些声音”后才允许覆盖；默认选项为保留手动设置并排除受保护轨道；
- 排除受保护轨道会削弱组合效果时，应说明结果差异，但不得把用户拖动过控件视为覆盖授权；
- 取消、撤销或离开页面时，受保护轨道保持原值。

## 5. 脚本替换

### A级：直接替换

替换组内素材已满足相同播放类型、时长策略、角色范围和运动预设，直接替换 `resource_key`，只重编当前轨。

### B级：单轨适配

素材语义兼容，但时长、循环或运动预设需要调整。只重编当前轨并重新校验，不重建整个场景。

### C级：结构重组

素材会改变角色、触发模式或脚本关系。进入后台处理或建议更合适的声音组合方式，不阻塞即时创建路径。

## 6. AI职责

AI可以在规则过滤后的候选中排序、推荐互补素材、选择已批准脚本和运动预设、把自然语言转换为可确认修改，并解释推荐原因。

AI不能临时猜测语义区域、绕过绑定和QC、输出未经校验的时间线、修改用户锁定或删除的声音、覆盖受保护轨道，或把普通物体动画当作声音触发器。

## 7. 数量上限

2026-09-20 契约修订：[槽位与角色契约冲突裁决 v2.0](./槽位与角色契约冲突裁决_v2.0.md)与机器脚本 `2.0.0` 已按本节上限同步。最小结构分别为：外部加内部稳定；底层加包围或细节；至少两个景深组；底层加一个焦点对象；背景加左/右/前至少一组。推荐结构不是必填结构，具体审核绑定仍可进一步限制可用组合。

- 用户可选声音组合方式：5 个；
- 内部框架定义：5 个，与声音组合方式一一对应；
- 结构脚本族：5 个；
- 正式内容预设：首版不超过 10 个；
- 稳定底层 `bed`：固定 1 个；
- 独立环境层 `ambience`：0–1 个；
- 前景声音池 `action + trigger + voice`：合计 0–3 个；
- 除稳定底层外，环境层与前景声音合计至少 1 个、最多 3 个；
- 普通声音物体总数：2–4 个，用户选择和系统补充均计入；
- 人声 `voice`：最多 1 个；
- 推荐候选：每次最多 3 个；
- 单声音运动预设：每次最多 3 个；
- 新增第六种声音组合方式前，必须证明其声音关系不能由当前五类表达。

`action`、`trigger` 和 `voice` 共享前景预算。若已有独立 `ambience`，前景最多 2 个；若没有独立 `ambience`，前景最多 3 个。物体音和触发音不能各自独立占满 2–3 个名额。

| 声音组合方式 | 推荐结构 | 建议总数 | 硬上限 |
| --- | --- | --- | --- |
| 内外交织 | 底层 1 + 外部环境 1 + 内部细节 0–2 | 3 | 4 |
| 安稳包围 | 底层 1 + 包围环境 1 + 细节 0–1 | 2–3 | 3 |
| 远近分层 | 远景底层 1 + 中景主体 1 + 近景细节 0–1 | 2–3 | 3 |
| 主声突出 | 底层 1 + 可切换物体／触发音 2–3 | 3–4 | 4 |
| 两侧舒展 | 背景 1 + 左右近场 2 + 可选正前人声 0–1 | 3–4 | 4 |

高注意力前景声音默认同一时刻只突出一个。增加对象种类用于事件轮换和内容变化，不代表允许多个触发音同时争夺注意力。超出当前组合方式硬上限时，引导替换现有对象或进入第三层深度创作。

## 8. 验收

- 每个第二层场景恰好选择一种声音组合方式，并保存一个内部控制器；
- 每种声音组合方式只有一个主要声学交互；
- 每个第二层场景恰好一个 `bed`，分类数量与组合方式硬上限同时通过；
- 用户选择和系统补充合计不超过四个普通声音物体；
- 每条即时候选都有 `approved` 绑定；
- 同一素材在同一内部框架只有一个默认绑定；
- 普通物体动画不会误导为声音触发；
- 删除、替换和微调不重建无关轨道；
- 保存的组合交互可以在第三层还原；
- 所有宏观控制都明确展示作用对象；
- 受保护轨道不会被静默覆盖，覆盖前有影响清单和明确确认；
- 状态切换无硬切、爆音、突然贴耳或不安全路径；
- 五种声音组合方式的主要状态都完成耳机、手机外放和长时试听后才能标记为正式。
