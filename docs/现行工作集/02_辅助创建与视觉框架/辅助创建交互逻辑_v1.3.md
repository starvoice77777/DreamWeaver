# DreamWeaver 辅助创建交互逻辑（声音组合方式）

2026-09-20 契约修订：槽位、区域、身份和角色校验统一采用[冲突裁决 v2.0](./槽位与角色契约冲突裁决_v2.0.md)。界面草稿允许未填满最小结构；最终生成同时满足框架上限、跨槽约束和角色预算。本文不表示新候选/生成服务已上线。

版本：`v1.3`

状态：现行交互基线

日期：2026-09-19

## 1. 定位

辅助创建面向希望获得个性化内容、但不愿操作时间轴和空间坐标的用户。

核心分工：

> 用户选择声音关系和想听的声音，系统用已审核脚本完成时间、音量和空间编排。

第二层不是简化版时间轴，也不是开放式AI聊天。主要操作是看、听、选择和拖动；自然语言只在必要时补充。

## 2. 总体流程

```text
进入辅助创作
→ 选择一种声音组合方式
→ 进入半完成画布
→ 试听并拖入核心声音
→ 系统推荐互补声音并增量编译
→ 确认用户选择与系统补充
→ 完整校验，同时描绘组合线稿
→ 首次试听
→ 调整声音组合或微调单个声音
→ 保存个人场景／进入深度创作
```

首页同时保留辅助创作和深度创作入口，用户不必先经过第二层。

## 3. 页面一：选择声音组合方式

页面只展示五种声音组合方式卡片，每张卡片包含：

- 一幅可理解声音关系的缩略线稿；
- 一句结果描述；
- 一个短试听或缩略动效；
- 点击进入，不先展示技术参数。

五种声音组合方式固定为：内外交织、安稳包围、远近分层、主声突出、两侧舒展。卡片以“声音会怎样组合”为中心，不使用“视觉框架”作为用户分类。图形造型可以继续调整，但声音关系和内部 `framework_id` 不随视觉文案变化。

| 用户名称 | 内部 `framework_id` |
| --- | --- |
| 内外交织 | `boundary_gate` |
| 安稳包围 | `enclosure_control` |
| 远近分层 | `depth_reveal` |
| 主声突出 | `focus_selector` |
| 两侧舒展 | `nearfield_width` |

## 4. 页面二：半完成素材画布

### 4.1 页面结构

- 中央：当前声音组合方式的半完成线稿和可接收声音的语义区域；
- 下方：最多三个动态推荐素材；
- 补充入口：搜索、分类浏览和一句话补充；
- 底部：创建条件与确认按钮；
- 已选声音以图标显示，不立即绘制完整物体线稿。

半完成画布只表达窗内／窗外、远／中／近或焦点对象等粗粒度关系，不要求用户操作精确坐标。

### 4.2 素材卡片

每张卡片只显示物体或声音名称、简单图形、单独试听、推荐理由短标签以及加入操作。卡片不展示 `scene_role`、坐标、响度数值和脚本名称。

### 4.3 拖入行为

用户拖入素材后：

1. 图标吸附到 `FrameBindingProfile.visual_zone` 对应区域；
2. 创建 `SceneDraft` 中的声音对象；
3. 锁定当前素材，不再允许AI静默替换；
4. 后台预取母带、选择默认角色和脚本轨道；
5. 推荐区根据当前缺少的声音职责更新。

拖入时先显示图标，不直接展示最终线稿。最终物体线稿在创建确认后的描绘阶段出现。

### 4.4 主动寻找

用户可以按可理解的声音类别浏览、搜索素材名称或输入一句补充。搜索结果仍受当前组合方式的内部框架适配、授权和QC约束。没有 `approved` 绑定的素材不能承诺即时加入，可以建议兼容的声音组合方式或进入后台适配。

## 5. 动态推荐

推荐不是一次展示大量入口，而是逐步缩小范围：

1. 第一个核心声音优先满足用户主动选择；
2. 第二个候选补足稳定底层或主要环境；
3. 第三个候选补足低密度细节；
4. 已满足最小结构后，不再强推更多声音；
5. 每次最多展示三个候选，并提供“换一组”。

AI只在规则过滤后的候选中排序。排序输入包括当前声音组合方式对应的内部框架、内容预设、已选素材、用户历史偏好、授权、QC和缓存状态。

## 6. 最小生成条件

用户最低选择一个核心声音即可请求创建。系统同时检查：

- 存在一个用户明确选择的声音；
- 可以解析出唯一的声音组合方式、内部 `framework_id` 和内容预设；
- 存在合法的稳定承接层，来源可以是用户选择或系统补充；
- 所有素材都存在当前组合方式对应内部框架的 `approved` 绑定；
- 恰好一个稳定底层 `bed`；
- 独立环境层 `ambience` 不超过一个；
- `action + trigger + voice` 共享最多三个前景名额；
- 环境层与前景声音合计不超过三个，普通声音物体总数不超过四个；
- `voice` 不超过一个。

数量按逻辑声音物体计算，不按录音文件或变体计算。用户选择和系统补充均占名额；同一声音物体轮换多个审核变体仍只占一个名额。

首次生成根据声音组合方式给出二至四个声音对象：环境型组合通常二至三个；“主声突出”和“两侧舒展”可以直接生成三个，用户主动选择或预设明确需要时最多四个。

如果需要补充稳定层，确认前必须明确展示用户选择、系统建议、试听、更换和不添加。系统补充声音带有独立标记；用户删除或拒绝后不能静默加回，只能提示“场景可能更空”。

用户添加声音时先检查分类预算，再检查当前组合方式硬上限。分类已满时，推荐替换同类声音或移除其他前景对象；尝试添加第五个声音，或超过当前组合方式硬上限时，引导替换现有声音或进入深度创作。系统不得静默删除已有对象来腾出名额。

## 7. 生成前的信息补充

系统按以下顺序确定内容策略：

1. 继承入口上下文、近期有效目标和用户已选声音；
2. 使用内容预设的默认状态和编排配置；
3. 仍有明显歧义时，只出现一组少量卡片；
4. 一句话输入作为可跳过的补充。

不能要求用户逐一描述声音出现时间、轨迹或音量。自然语言先转换为可见、可撤销的修改建议，确认后才写入草稿。

## 8. 创建与等待反馈

确认按钮不从零启动长时间AI生成。系统在用户选择过程中已经完成索引加载、母带预取、脚本匹配和受影响轨道的局部编译。

确认后按顺序展示：

1. 已选图标保持原位；
2. 系统补充图标显式出现；
3. 从声音组合方式的图形主线开始描绘；
4. 在各图标位置逐步画出相应物体线稿；
5. 同步完成时间线、引用、循环和路径校验；
6. 最小可播放版本就绪后立即进入试听。

线稿动画是进度反馈，不虚构具体百分比。只使用“整理声音关系、连接空间层次、检查播放安全、场景已可试听”等可解释阶段。

若五秒内仍无法得到最小可播放结果，保留组合并提供继续等待、使用默认安全版本或稍后完成。未适配上传素材、AI生成新素材和C级脚本重组进入后台任务，不阻塞当前快速路径。

## 9. 首次试听页

页面包含完整组合线稿、当前声音组合方式的一个宏观声学交互、每个声音的可选标记、播放控制、保存、深度创作以及一句补充入口。

普通物体可以有装饰动效，但默认不触发声音，也不改变时间线。用户通过声音标记选中并编辑对应声音。

## 10. 声音组合交互

| 声音组合方式 | 图上操作与等价控件 | 声学作用（基线） | 提交反馈 |
| --- | --- | --- | --- |
| 内外交织 | 拉帘／开合；同参数滑杆 | `boundary_openness: 0..1`；外部相对突出程度变化，内部稳定或小幅补偿 | 松手后显示“已调整窗外声音 · 撤销” |
| 安稳包围 | 包围结构吸附到三档；开阔／均衡／安稳按钮 | `open / balanced / enclosed`；稳定底层、未来细节密度与运动范围按审核方案改变 | 提示从后续事件生效 |
| 远近分层 | 选近处／均衡／远处；对应层高亮 | `near / balanced / far`；相对混音与三套审核距离状态 | 展示当前突出层，不显示任意坐标 |
| 主声突出 | 拖焦点指示器到对象；或点主声目标按钮 | `focus_target: sound_object_id`；最多三个可选目标，影响持续声音主次及未来事件 | 显示当前主声名；不会立刻播放一次性事件 |
| 两侧舒展 | 两侧结构收拢／展开并吸附三档；集中／自然／舒展按钮 | `focused / natural / wide`；使用审核过的近场运动预设 | 提示从下一事件或安全段落生效 |

共同规则：

- 每个宏观控制必须在界面上说明当前作用的声音组或具体声音；
- 拖动过程中允许使用临时播放参数即时预听；
- 松手或选择离散状态后显示可撤销结果；
- 保存场景时把状态写入 `framework_controller`；
- 影响最终混音、事件密度或空间的变化会重新编译受影响内容，并使 `timeline.version + 1`；
- 当前短触发不被硬停或突然改道，变化从安全边界生效；
- 内外交织不改变素材种类、事件时序和运动路径，也不假设低通、遮挡或动态混响可用；
- 远近分层不改变声音角色和事件频率；两侧舒展不改变触发频率；主声突出不删除其他对象。

### 10.1 手动调整保护

被单声音轻量微调或在第三层手动编辑过的轨道，默认进入 `manual_override_track_ids` 并受保护。宏观控制若会改动这些轨道：

1. 先展示影响清单，列明声音名称、轨道标识和将变化的维度；
2. 默认保留手动设置，并从本次宏观调整中排除；
3. 只有用户明确选择“仍应用到这些声音”后才允许覆盖；
4. 仅仅拖动过一次控件不构成覆盖授权；
5. 如果排除后组合效果会减弱，界面说明差异，但不替用户作决定。

## 11. 单个声音的轻量微调

第二层只保留三项：

### 11.1 同类声音

系统先推荐最多三个同替换组候选。候选可以点按试听，但不要求用户遍历整个素材库。替换只重编当前轨道。界面显示具体声音名称或可听结果，不使用“换一种”“颗粒感”等含糊文案。

### 11.2 音量

只使用“更轻／保持／更明显”三个主观档位，不显示数值。距离不作为第二层独立参数；工程中的音量和距离仍分别保存。

### 11.3 移动方式

只展示当前角色允许且已试听的最多三个运动预设。选项使用运动缩略动画和结果名称，不让用户画轨迹或设置坐标。

每次调整支持试听、应用、撤销。用户手动调整后，该轨加入 `manual_override_track_ids`。

## 12. 删除

用户长按声音图标或声音标记并拖出画布即可删除，随后提供撤销。删除操作与第三层保持一致，不额外占用微调选项。

删除后系统不自动补回。若删除稳定层，只提示可能影响场景完整性，让用户自行决定是否更换。

## 13. 自然语言

自然语言仅在三个位置出现：

1. 生成前补充卡片和素材选择未覆盖的偏好；
2. 生成后表达快捷选项无法覆盖的修改；
3. 异常恢复时寻找兼容素材或解释限制。

系统必须把自然语言转换为具体、可确认的操作，不能直接执行无法解释的开放生成。

## 14. 保存与进入第三层

保存内容至少包括场景目标与预设、声音组合方式及内部控制器状态、声音来源、最终角色、时间、音量、空间、手动调整记录、时间线版本、授权和QC状态。

进入第三层时直接展开当前标准时间线，不重新生成。第三层可以继续添加轨道和编辑关键帧；第二层声音组合状态转成可见的轨道和控制点。

## 15. 页面状态

```text
selecting_framework
loading_candidates
editing_canvas
previewing_asset
preparing_draft
ready_to_create
compiling
playable
adjusting_framework
adjusting_sound
saving
background_processing
error_recoverable
```

`selecting_framework`、`adjusting_framework` 是兼容既有实现的内部状态名，用户界面统一显示“选择声音组合方式”和“调整声音组合”。

任何失败都保留已选图标和草稿，不清空用户操作。

## 16. 验收

- 用户可以不输入文字完成创建；
- 推荐区一次不超过三个候选；
- 每个场景恰好一个稳定底层，环境层最多一个；
- 动作音、物体音、触发音和人声共享前景预算，不会分别占满三项配额；
- 用户选择与系统补充合计不超过当前组合方式硬上限，且绝不超过四个普通声音对象；
- 系统补充与用户选择可辨认；
- 拖入后先显示图标，确认后逐步描绘线稿；
- 用户能删除、同类替换、调主观音量和选择运动预设；
- 声音组合交互与普通物体动效不会混淆；
- 五种组合方式均有明确作用对象、等价控件和提交反馈；
- 受保护轨道不会被宏观控制静默覆盖；
- 第二层结果无损进入第三层；
- 快速路径失败时仍保留草稿并提供安全回退。
